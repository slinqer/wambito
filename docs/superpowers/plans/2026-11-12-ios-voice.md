# iOS voice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The voice button works on iOS with sherpa-onnx only (Canary es/en, Parakeet it/pt), live text included, models downloaded on first use.

**Architecture:** A Swift `wambito/voice` channel (`ios/Runner/Voice/`) records with `AVAudioEngine` and decodes with a statically linked sherpa-onnx; its pure logic lives in `ios/WambitoNative` with `swift test`. Dart gets a `PreciseEngine` chosen on iOS, and on iOS the voice model store is the precise one. sherpa-onnx for iOS is built once with upstream's `build-ios.sh`, kept in a release of this repo, and fetched with a pinned SHA-256.

**Tech Stack:** Swift 5.9 / iOS 16, AVFoundation, Compression, sherpa-onnx 2.0.1 + onnxruntime 1.28.2 static xcframeworks, Flutter/Dart (Riverpod), bash.

**Spec:** `docs/superpowers/specs/2026-11-12-ios-voice-design.md`

## Global Constraints

- Paths: `ios/`, `lib/`, `test/` and `scripts/<name>-ios.sh` are under `apps/mobile/`; `.github/`, `docs/` and `scripts/check-*.sh` are at the repo root.
- Branch `feat/ios-voice` (from `feat/ios-base`). Commits `feat(ios): …`, `test(ios): …`, `ci(ios): …`, `docs: …`; lowercase; no `Co-Authored-By` line; stage by path.
- Android behaviour does not change: `VoskEngine`, `VoiceChannel.kt` and the Android download flow are untouched.
- Same channel names, method names, argument keys, event maps and error codes as `android/.../voice/VoiceChannel.kt`: events `ready`, `level`, `partial`, `refining`, `refined`, `refine_failed` (`timeout`|`failed`), `done`, `error` (`permission`, `mic_unavailable`, `bad_arguments`, `no_model`, `failed`); no `result` on iOS.
- Audio: 16 kHz mono, 40 ms chunks (640 samples), buffer cap 30 s (480 000 samples), level = RMS dBFS with floor −50 mapped to 0..1.
- Live decode first at 1 s (16 000 samples), then every 0.5 s (8 000 samples); final decode limit 3 s; recognizer 2 threads, provider `cpu`.
- RAM: 3 GiB (3 × 1024³) default, Parakeet 5 GiB (from `VoiceModel.minRamBytes`).
- Parakeet is the folder with `joiner.int8.onnx`; else Canary.
- sherpa-onnx v2.0.1 commit `af2d8d81dbfa61c4cea4c568da78f3982edca005`; onnxruntime asset `onnxruntime-ios-static-xcframework-1.28.2.xcframework.zip`, 33821118 bytes, from `csukuangfj/onnxruntime-libs` release `v1.28.2`.
- Our release tag `ios-sherpa-onnx-2.0.1`, asset `sherpa-onnx-ios-2.0.1.zip`, installed to `apps/mobile/ios/third_party/sherpa-onnx/` (git-ignored). Uploading it is an outward action: stop and ask the founder first.
- Never hand-edit generated files; never read `.env` or secrets; no personal names or paths in the repo. Fixtures are invented.
- Files added to Runner or RunnerTests go into `project.pbxproj` by hand (the target is not a synchronized group).

## Review Focus

1. The person releases the button within the first second (no live decode ran yet): the final pass still runs and the text is the final decode, never empty because no partial came. → Task 7 (`PreciseEngine` test "short sentence with no partial ends with refined").
2. Another app plays music, then voice ends with an error (no model, permission): the audio session still goes back to `.ambient` and deactivates. → Task 6 (session restore on every exit path, `VoiceSession` test in WambitoNative).
3. A model zip half-downloaded or corrupt reaches `unzip`: no partial folder is left that `ModelStore` could take for a model. → Task 3 (`ZipExtract` truncated-file test).
4. Italian on a 4 GiB iPhone: voice is not offered (Parakeet needs 5 GiB) instead of downloading 670 MB that cannot load. → Task 8 (capture session test).
5. `stop` called twice, or `stop` after an error: one `done`, no crash. → Task 7 (Dart, second `stop` is a no-op) and Task 6 (`VoiceRun` ignores a second stop).

**Interfaces:**
- Produces: `public enum ZipExtract { public static func unzip(_ zip: URL, into: URL) throws }` and `public enum ZipError: Error, Equatable { case notZip, unsupported(String), outside(String), truncated }`.
- Reads the central directory (end record at the file's tail), then each local header; methods 0 (stored) and 8 (deflate, via `compression_stream` with `COMPRESSION_ZLIB`, which is raw deflate); encrypted flag, zip64 sizes (`0xFFFFFFFF`) or any other method → `unsupported`. On any throw, removes everything it created under `into` (the caller's staging folder is then empty).
