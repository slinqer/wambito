# Authenticated key versions Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Every key version after the first carries a link back to the previous data key, so a device
accepts a new version only when the links lead back to a key it already holds. Removing a device
also ends its session.

**Architecture:**
- `packages/crypto` gains `sealKeyLink`/`openKeyLink`, with vectors.
- The API stores one link per rotation in a new `key_links` table and returns the links with the
  wraps.
- The web checks the chain wherever it opens DK from its device wrap at a version above its own
  (`refreshKeys`, `withDataKey`), and walks the chain down after a passkey, recovery or pairing
  unlock.
- Device wraps remember the session that registered them; the server deletes that session when the
  wrap goes away.

**Tech Stack:** TypeScript, WebCrypto, Hono + zod-openapi, Drizzle + Postgres RLS, Better Auth, React
Router, Vitest, Playwright.

**Spec:** `docs/superpowers/specs/2026-11-10-e2e-key-links-design.md`. It amends
`2026-11-08-end-to-end-encryption-design.md` and `2026-11-08-e2e-stage-1b-design.md`.

## Global Constraints

- **Branch** `docs/e2e-key-links` (the spec is already committed there).
- **Commits:**
  - Conventional Commits in the repo style (`feat(crypto): …`, `feat(api): …`, `feat(web): …`), a
    lowercase sentence;
  - never a `Co-Authored-By` line;
  - stage by path, never `git add -A`.
- **Tests and language:** write the failing test first; everything in English.
- **Link format** (verbatim from the spec):
  - `linkKey(v) = HKDF-SHA256(DK(v), salt = empty, info = "wambito/v1/link")`, used as an
    AES-256-GCM key;
  - `link(v) = nonce (12 bytes) || AES-256-GCM(linkKey(v), DK(v-1))` for v ≥ 2;
  - associated data `"wambito/v1/link/<user id>/<v>"`;
  - a link is 60 bytes.
- **API errors:**
  - 422 `link_required` (rotation of an account that has a version);
  - 422 `link_unexpected` (link on the first version);
  - 422 `invalid_link` (not 60 bytes).
- **Generated files are regenerated, never hand-edited:**
  - `pnpm --filter @wambito/web api:types --file`;
  - `pnpm --filter @wambito/mcp api:types`;
  - `apps/mobile/scripts/gen-api.sh`;
  - migrations through `pnpm --filter @wambito/db generate`.
- **CHANGELOG:** every API change adds a line under "Unreleased" in the root `CHANGELOG.md`.
- **Secrets:** never read `.env` files or secrets. A data key, PRF output or link plaintext is never
  logged.
- **Tests:** Docker must run for the API and DB tests (or `WAMBITO_TEST_DB=local`).
- **Copy:** Spanish copy uses "clave de recuperación" and "passkey", as the app does today. Italian
  and Portuguese are faithful translations of the English given here.

## Review Focus

1. **A lost rotate answer, retried.** `rotate.ts` `commit()` must post the same `link` on the
   retry, and `landed()` must still recognise the rotation as ours. Test in Task 6.
2. **A device wrap whose session is already gone** (expired, signed out: `session_id` is null).
   Removing that device or rotating it away revokes nothing and does not fail. Test in Task 4.
3. **The rotating browser removes another device.** Its own session survives even though its old
   device wrap row is deleted and re-inserted by the rotation. Test in Task 4.
4. **A fresh unlock on an account whose oldest link is missing** (rotated before this change). The
   unlock still succeeds at the current version and keeps only what the chain reaches; it is never
   `tampered`. Test in Task 5.
5. **A `tampered` refresh must not lose unsent edits.** The vault stays, the outbox is kept, and
   after unlocking with the recovery key the outbox syncs under the verified version. Test in
   Task 7.

### Task 5: The web checks the chain

**Files:**
- Modify: `apps/web/app/local/keys.ts`.
- Test: `apps/web/app/local/keys.test.ts` (its fake server gains `links`).

**Interfaces:**
- Consumes: `openKeyLink` (Task 1), `GET /v2/keys` `links` (Task 3).
- Produces, all in `keys.ts`:
  - `listKeys(call: KeysApi): Promise<{ wraps: WrapDto[]; links: Map<number, Uint8Array> }>`;
    `listWraps` stays as a wrapper.
  - `chainDown(userId: string, top: { keyV: number; dataKey: Uint8Array }, links: Map<number, Uint8Array>, floor: number, strict: boolean): Promise<Map<number, Uint8Array>>`
    returns the data keys for the versions `top.keyV - 1` down to `floor`.
    - `strict`: a missing or failing link throws `KeysError("tampered")`.
    - Not strict: the walk stops at the first missing or failing link and returns what it reached.
    - On a throw it zeroes everything it opened.
  - `refreshKeys` keeps `record:<v>`/`dedupe:<v>` for every version from `c + 1` to `n`.
  - `withDataKey` refuses an unverified version.
  - `keepLocally(userId, dataKey, keyV, device, older: Map<number, Uint8Array>)` stores the older
    versions too.
  - `enrollDevice(options, dataKey, keyV, pair)` keeps its signature and walks the links itself
    (not strict).

- [ ] **Step 1: Write the failing tests** in `keys.test.ts`. Replace `a wrap at a keyV this browser does not hold yet is not checked (a rotation)`
  with:
  - `withDataKey refuses a forged v+1: no link, or a link to another key, is tampered; fn never runs`;
  - `refreshKeys refuses a forged v+1, keeps nothing, and current stays v`;
  - `refreshKeys at v reaching v+2 keeps v+1 and v+2, and a record sealed under v+1 opens`;
  - `a broken middle link (v+2 → v+1 fine, v+1 → v wrong) is tampered and keeps nothing`;

    (Review Focus 4);
  - `unlockWithPasskey on a browser holding v whose chain does not reach its key is tampered`;
  - `enrollDevice (pairing) keeps the older versions the links reach`.

  - When `keyV` is above the held current `c`, it calls `chainDown(…, c, true)` and checks
