# E2E stage 1b implementation plan

> **For agentic workers:** execute task by task. Each task writes its failing tests first, then commits on its own.

**Goal:** close the four gaps the main spec's section 17 lists, before any client depends on the
server.

**Spec:** `docs/superpowers/specs/2026-11-08-e2e-stage-1b-design.md`, the addendum. It wins over
`docs/superpowers/specs/2026-11-08-end-to-end-encryption-design.md`.

**Branch:** `feat/e2e-stage-1b`, cut from `main` after PR #54.

## Global constraints

- Follow the root `AGENTS.md` and the `AGENTS.md` of each area you touch.
- Tests come first. Everything is written in English.
- Commits use Conventional Commits and are staged by path. Never add a `Co-Authored-By` line.
- Never hand-edit a generated file. Regenerate the client types with the commands in the root
  `AGENTS.md`.
- Every API change gets a line under "Unreleased" in the root `CHANGELOG.md`.
- Every new error code gets web i18n strings in `apps/web/app/i18n/messages/app.{en,es,it,pt}.json`.
  The pt strings use informal "tu".
- Never log or interpret opaque bytes.
- Every SQL statement filters on the user id explicitly, on top of RLS.
- Ids are lower-case UUIDs; never lower-case them for the caller.

## Task 1: crypto (`packages/crypto`)

1. Add `pairingCommitment(publicKey: Uint8Array): Promise<Uint8Array>` to `src/pairing.ts`. It
   returns `SHA-256(utf8("wambito/v1/pairing-commit") || publicKey)` and asserts that the key is
   32 bytes.
2. Give `sealToDevice(publicKey, ctx, dataKey, ephemeral?)` in `src/devices.ts` an optional
   fourth argument, `ephemeral?: { publicKey: Uint8Array; privateKey: DevicePrivateKey }`. When it
   is given, the seal uses that pair instead of making a new one.
3. Add `openFromPairing(privateKey, ctx, sealed, approverKey: Uint8Array)`. It throws
   `CryptoError("cannot_open")` unless `sealed` starts with `approverKey`, then does what
   `openFromDevice` does. Compare in constant time.
4. In a new file `src/attest.ts`, add `deviceAttestation(dataKey, { userId, wrapId, publicKey })`,
   returning a `Promise<Uint8Array>`, and `verifyDeviceAttestation(dataKey, input, attestation)`,
   returning a `Promise<boolean>`.
   - Build them exactly as spec section 2 says, with WebCrypto HKDF and HMAC.
   - Validate `userId` and `wrapId` with the existing validators: the user id regex, and wrap ids
     as lower-case UUIDs.
   - `verifyDeviceAttestation` returns false for an attestation of the wrong length.
   - Export everything from `src/index.ts`.
5. Write the tests in `test/`.
6. Extend `scripts/gen-vectors.ts` to cover:
   - `pairingCommitment`;
   - `pairingNumber` with (new-device key, approver key);
   - `sealToDevice` with a fixed ephemeral key;
   - `deviceAttestation`;
   - a rejection in `rejects` for an `openFromPairing` blob with the wrong approver key.

   Then regenerate with `pnpm --filter @wambito/crypto vectors` and make sure the vector test reads
   the new sections.
7. Update `packages/crypto/AGENTS.md`.
8. Commit as `feat(crypto): pairing commitment and device attestation`.

## Task 2: database (`packages/db`)

1. Add the migration `drizzle/0011_end_to_end_gaps.sql`, keeping the `meta` journal and snapshot
   in step the way the earlier migrations do:
   - **`pairing_requests`:** `delete from pairing_requests`. Add `commitment bytea not null`
     (length 32), `approver_key bytea` (length 32), `key_v smallint`, and make `public_key`
     nullable (length 32 when set). Keep the code index.
   - **`key_wraps`:** add `attestation bytea`, with the check
     `kind <> 'device' or (attestation is not null and octet_length(attestation) = 32 and public_key is not null and octet_length(public_key) = 32)`.
   - **`record_purges`:** `(user_id text primary key references "user"(id) on delete cascade, through_version bigint not null)`.
     Give it the same RLS as `records`: a `tenant_isolation` policy and FORCE. Grant the runtime
     role what `records` gets.
2. Update the matching Drizzle tables in `src/schema/domain.ts` and add `record_purges` to
   `RLS_TABLES`.
3. Extend `test/records-rls.test.ts`, or add a test next to it, covering:
   - RLS isolation of `record_purges`;
   - the attestation check;
   - the length checks of the pairing columns.
4. Update `packages/db/AGENTS.md` if it lists migrations or tables.
5. Commit as `feat(db): pairing commitment, device attestations, record purges`.

## Task 3: the pairing relay (`apps/api`)

1. Rewrite `src/services/pairing.ts` and `src/routes/pairing.ts` to follow spec section 1.
   - **`POST /v2/pairing`:** body `{ commitment }`, base64url of 32 bytes.
   - **`GET /v2/pairing?code=`:** returns `{ id, commitment, expiresAt }`, only for a request with
     no approver key yet. Otherwise 404.
   - **`POST /v2/pairing/{id}/approver`:** body `{ publicKey }`. 409 `already_set`.
   - **`POST /v2/pairing/{id}/reveal`:** body `{ publicKey }`. 409 `not_ready` when there is no
     approver key, 409 `already_set` when the key was already revealed, 422 `commitment_mismatch`.
     The server computes the commitment with `pairingCommitment` from `@wambito/crypto`.
   - **`POST /v2/pairing/{id}/seal`:** body `{ sealed, keyV }`. 409 `not_ready` without a revealed
     key, 409 `already_sealed`, 422 `approver_mismatch` when the first 32 bytes of `sealed` are not
     the approver key.
   - **`GET /v2/pairing/{id}`:** returns the full state and deletes the row when it is sealed.
   - Every write takes the existing lock.
2. Tests in `test/pairing.test.ts`:
   - the happy path with real crypto from `@wambito/crypto`: the new device opens the result with
     `openFromPairing`;
   - every out-of-order call and each error;
   - expiry;
   - another person's id gives 404;
   - assistant tokens get 403.
3. Add the error codes to the web i18n, regenerate the web, MCP and mobile client types, and add the
   CHANGELOG lines (under Changed: the pairing relay now uses a commitment). Update
   `apps/api/AGENTS.md`: rewrite the `/v2/pairing` bullet and remove the "Pairing number" known gap.
4. Commit as `feat(api): pairing relay with a key commitment`.

## Task 4: attestations and the resync signal (`apps/api`)

1. In `src/services/keys.ts` and `src/routes/keys.ts`:
   - **`PUT /v2/keys/{id}` and `POST /v2/keys/rotate`:** a `device` wrap needs `publicKey` and
     `attestation`, both base64url of 32 bytes; otherwise 422 `attestation_required`. Other kinds
     must not send `attestation` (422 `bad_request`, or whatever the existing validation code is).
   - **`GET /v2/keys`:** returns `attestation`.
2. In `src/services/sync.ts`:
   - **`purgeTombstones`:** in the same transaction, upsert `record_purges.through_version` to
     `greatest(old, max purged version)` for each person it purges.
   - **`pullRecords` and the `GET /v2/sync` route:** answer 410 `resync_required` when
     `0 < since < through_version`.
3. Tests: in `test/keys.test.ts`, the attestation rules; in `test/sync.test.ts`, the 410 after a
   purge, and 200 for `since=0` and for `since >= through_version`.
4. Add the i18n codes, regenerate the types, and add the CHANGELOG lines. Update
   `apps/api/AGENTS.md`: the `/v2/keys` and `/v2/sync` bullets, and remove the "Device keys in
   rotation" known gap.
5. Commit as `feat(api): device attestations and a resync signal`.
