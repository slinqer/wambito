# E2E stage 4: the MCP reads encrypted accounts — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A connected assistant works on an end-to-end encrypted (`preview`) account: the web's
consent page gives it a key, the API carries the assistant's secret `S` inside its tokens, and the
MCP opens the account's records in memory per request and answers through the web's own local
backend.

**Architecture:** The web's local backend and sync engine move, unchanged, into a new browser-free
package `packages/vault`, which gains an in-memory encrypted store. The API wraps Better Auth's
OAuth endpoints to carry `S` (refresh token suffix, a JWE `wk` claim for the MCP). The MCP, for a
token with `wk`, opens the `assistant` wrap, syncs into an in-memory store and hands its tools the
local backend's `fetch` through the existing `apiWambito`.

**Tech Stack:** TypeScript, Hono, Better Auth 1.7.11 (`@better-auth/oauth-provider`), `jose`
(compact JWE), WebCrypto, Vitest (+ testcontainers through `apps/api/test/harness.ts`), React
Router (web), Flutter l10n (phone copy only).

**Spec:** `docs/superpowers/specs/2026-11-16-e2e-stage-4-mcp-design.md` (approved 2026-11-16).
Parent: `docs/superpowers/specs/2026-11-08-end-to-end-encryption-design.md` section 9. Spike
evidence for the token wrapper: `docs/superpowers/reports/2026-11-08-e2e-spikes.md`, "Assistant
secret in tokens" (hook locations in Better Auth's dist files are listed there).

## Global Constraints

- `plain` accounts behave exactly as today: same tokens (no `.` suffix, no `wk`), same MCP path
  (`apps/mcp/src/api-wambito.ts` over `/v1`), same consent page.
- `S` is 32 random bytes, base64url (43 characters). It travels only in the consent POST body (as
  `wk`), the refresh token (`<better-auth token>.<S>`, split on the last `.`) and the access
  token's `wk` claim (a compact JWE, `ECDH-ES` + `A256GCM`, to the MCP's public key).
- `S`, the data key, record keys and decrypted bodies never reach a database column, a log line, an
  error message, a problem+json body or a cache. The MCP's cache holds only what `/v2/sync` sent
  (encrypted) and the cursor.
- The code → `S` map lives in API process memory, entries expire after 10 minutes and are deleted
  on exchange whatever happens.
- New error codes, exactly: `400 invalid_grant` (token endpoint, encrypted account without `S`),
  `503 assistant_keys_missing` (consent with `wk` and no `MCP_WK_PUBLIC_KEY`), `422
  assistant_wrap_in_rotation` (`POST /v2/keys/rotate` carrying an `assistant` wrap).
- New config, exactly: `MCP_WK_PUBLIC_KEY` (API), `MCP_WK_PRIVATE_KEY` (MCP), each a JWK as a JSON
  string.
- New package name: `@wambito/vault` at `packages/vault`, entry `./src/index.ts`, no browser API
  inside (no `indexedDB`, `window`, `navigator`, `BroadcastChannel`, Web Locks).
- Every movement the MCP creates has `source: "mcp"`.
- The MCP never re-seals records and a read tool never calls `POST /v2/sync`.
- The tools' input and output shapes in `packages/ai-assistant-tools` do not change.
- API changes get lines under "Unreleased" in the root `CHANGELOG.md`.
- Generated files are regenerated, never hand-edited: `apps/web/app/api/schema.d.ts`
  (`pnpm --filter @wambito/web api:types --file`), `apps/mcp/src/api/schema.d.ts`
  (`pnpm --filter @wambito/mcp api:types`).
- Copy in the four languages (en, es, it, pt) for every new or changed message, web and phone.
- Repo rules: tests first (RED before GREEN); English; money in integer cents; invented fixtures;
  Conventional Commits with a lowercase sentence, staged by path, never `git add -A`, never a
  `Co-Authored-By` line; never read any `.env` file; whoever changes an area's structure updates
  its `AGENTS.md`.

## Review Focus

1. **The API restarts between consent and code exchange** (the map loses `S`): the exchange is
   refused with `400 invalid_grant`, the client is revoked for that account, and the next connect
   shows the consent page again. Test in Task 5.
2. **Two tool calls of one assistant at the same moment** on one account: they run one after the
   other in the MCP and neither loses the other's write. Test in Task 9.
3. **Revoked while an access token is still valid** (inside its 15 minutes): the next tool call
   gets the "disconnected, connect it again" error, not data. Test in Task 10.
4. **A record still under an older key version** (a rotation whose re-seal is not finished, then a
   new connection): the MCP opens it through the key links and its figures count. Test in Task 9.
5. **A second call on a large account pulls only what changed** (the cache), and a cache entry is
   dropped on `410 resync_required` or a new key version. Test in Task 9.
