# iOS base Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The Flutter app in `apps/mobile` builds for iOS from the repo, with every Android native
channel except automatic capture, widgets and voice written in Swift, and CI that builds it on PRs
and uploads it to TestFlight from a `mobile-v*` tag.

**Architecture:** `apps/mobile/ios/` is a regenerated Flutter iOS target. Each channel is a thin
Swift handler in `ios/Runner/<Area>/` that keeps the Kotlin channel's name, methods, arguments,
results and error codes. Everything that needs no UIKit lives in a local Swift package,
`ios/WambitoNative`, which the Runner links and `swift test` runs on the Mac with no simulator.
Dart changes are limited to secure-storage options, two iOS copy variants and one widget guard.

**Tech Stack:** Flutter (pinned in `.flutter-version`), Swift 6 / Xcode 27, iOS 16+, XCTest,
`UNUserNotificationCenter`, `BGTaskScheduler`, `AuthenticationServices`, GitHub Actions
`macos-latest`, Caddy (deploy).

**Spec:** `docs/superpowers/specs/2026-11-11-ios-base-design.md`

**Deviation from the spec, on purpose:** the spec puts the pure-logic tests in `RunnerTests`. They
go in `ios/WambitoNative/Tests` instead, so they run with `swift test` on any Mac (no simulator
runtime is installed on the development Mac, and installing one is ~8 GB). `RunnerTests` keeps
only the generated smoke test. The `ios` CI job runs `swift test` as well.

## Global Constraints

- Bundle id `com.wambito.app`; display name `Wambito`; `IPHONEOS_DEPLOYMENT_TARGET = 16.0`.
- No team id, personal name, email or path in the repo; `DEVELOPMENT_TEAM` only in the
  git-ignored `ios/Flutter/Signing.xcconfig`.
- Channel names, method names, argument keys, result shapes and error codes are copied from the
  Kotlin side verbatim; a Dart wrapper never changes to suit iOS.
- Associated domains `webcredentials:app.wambito.com`, `applinks:app.wambito.com`; Universal Links
  only for path `/auth/verify` (the Android App Link path).
- Background task id `wambito.notice.due`; guest notification id `wambito.notice.guest`; guest delay
  44 days; due time 9:00 in the profile's zone.
- `flutter_secure_storage` on iOS: `KeychainAccessibility.first_unlock_this_device`.
- Sounds respect the silent switch (`AVAudioSession` category `.ambient`).
- Everything in English; Conventional Commits `feat(ios): …`, `test(ios): …`, `ci: …`; no
  `Co-Authored-By` line; stage by path.
- Generated files are regenerated, never hand-edited: the iOS icon set (`gen-icon.cjs`) and the
  notice strings (`scripts/gen-ios-strings.dart`).
- Write the failing test first.
- Commands assume `export PATH="$HOME/development/flutter/bin:$PATH" LANG=en_US.UTF-8` and the
  working directory `apps/mobile` unless a step says otherwise.

## Review Focus

1. A Keychain item written before Task 3 (the local test install) with the default accessibility
   is unreadable from a background task while locked: after Task 3 the app must rewrite the session
   items with the new option on its next start (Task 3, test `rewrites items stored with the old
   accessibility`).
2. A `wambito://` link or a notification tap arriving while the app is already running must reach
   Dart through `linkArrived`, not only at cold start (Task 7, test
   `a link while running is kept and announced`).
3. `pick` called twice before the first finishes answers `busy`, and cancelling the picker answers
   `null`, never leaves the Dart future hanging (Task 8, tests `second pick is busy`,
   `cancel answers null`).
4. "Hoy vence…" on a day with a DST change in the profile's zone, and with a zone string the phone
   does not know: the next run date falls back to the phone's zone, never crashes (Task 11, tests
   `next nine across DST`, `unknown zone falls back`).
5. The AASA file with no `IOS_TEAM_ID` set is still valid JSON served with 200, never a 404 or a
   broken file, and a malformed team id is skipped with a warning (Task 9, test-web-entrypoint
   cases `empty`, `malformed`).

- Produces: `public struct HapticSpec: Equatable { public let waveform: [Int]; public let
  primitives: [PrimitiveStep]; public static func parse(_ arguments: Any?) -> HapticSpec? }`,
  `public struct PrimitiveStep: Equatable { name: String; scale: Double; delayMs: Int; var
  fallback: String? }` with the Kotlin limits (`MAX_STEPS = 32`, `MAX_MS = 1000`, known names

  delayed by the sum of the waveform values before it.
  `HapticsChannel` answers `vibrate`: `bad-pattern` error when `parse` is nil, else plays the steps
  with `UIImpactFeedbackGenerator(style:).impactOccurred(intensity:)` scheduled by delay and answers
  `true`.

  `[(0, rigid, 0.5), (40, heavy, 1.0)]`; for waveform `[30, 60, 30]` with no primitives is
