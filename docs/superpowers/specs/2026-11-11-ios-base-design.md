# iOS base: the phone app on the App Store

Status: design, 2026-11-11. First of two parts; the second, voice on iOS (the `wambito/voice`
channel in Swift with Vosk and sherpa-onnx), gets its own spec once this one is merged.

## 1. Goal

The Flutter app in `apps/mobile` ships on the App Store, published by the Slinqer S.A.S.
organization account, with the same features as Android except the two iOS cannot have yet:

- in: everything the Dart code does today, plus the native channels `wambito/device`, `haptics`,
  `sounds`, `launch`, `files`, `passkeys` and `notices`, written in Swift;
- out on iOS: automatic capture from bank notifications (`wambito/capture`; iOS gives no app
  another app's notifications) and the home-screen widgets (they need WidgetKit, later);
- out of this spec: voice (part two). Until then the voice button behaves as on a phone without
  the models: `VoiceChannel.supported` catches the missing channel and answers false.

Success: a build uploaded to TestFlight by CI from a `mobile-v*` tag, which on a real iPhone signs
in with a passkey, imports and exports a CSV, opens `wambito://review/<id>`, and posts the guest
notice and "Hoy vence…".

## 2. The `ios/` folder

- Generated by `flutter create --platforms=ios --org com.wambito`, then: bundle id
  `com.wambito.app` (the Android application id), display name "Wambito", deployment target iOS 16
  (the first with platform passkeys through `ASAuthorization`).
- The app icon: `docs/brand/tools/gen-icon.cjs` also writes
  `ios/Runner/Assets.xcassets/AppIcon.appiconset` from `docs/brand/wambito-icon.svg` (square, plum
  corners, no alpha, every size the set lists). Generated, never hand-edited, like the Android
  mipmaps.
- Signing stays out of the repo: `project.pbxproj` has no `DEVELOPMENT_TEAM`; it comes from
  `ios/Flutter/Signing.xcconfig` (git-ignored, included by `Debug`/`Release`/`Profile.xcconfig`
  with `#include?`), and `Signing.xcconfig.example` documents it. A guard (§6) fails on any
  `DEVELOPMENT_TEAM = <value>` in the project.
- `Info.plist`: `CFBundleURLTypes` with `wambito`; usage strings (microphone, for part two, and
  notifications) in es, en, it and pt through `InfoPlist.strings`; `ITSAppUsesNonExemptEncryption`
  `NO` (the end-to-end encryption uses standard algorithms only; the exemption is confirmed in App
  Store Connect); `BGTaskSchedulerPermittedIdentifiers` with `wambito.notice.due`;
  `UIBackgroundModes` `fetch`.
- Entitlements: Associated Domains `webcredentials:app.wambito.com` and
  `applinks:app.wambito.com`.
- `PrivacyInfo.xcprivacy`: no tracking, no tracking domains; financial info and user content
  collected for app functionality only, linked to the account; the required-reason APIs the app
  and its plugins use (`UserDefaults`, file timestamps), each with its reason code.

## 3. Native channels

One folder per area in `ios/Runner/` (`Device/`, `Haptics/`, `Sounds/`, `Launch/`, `Files/`,
`Passkeys/`, `Notices/`), mirroring `android/.../kotlin/com/wambito/app/`. Each channel keeps the
Android channel's name, methods, argument keys, result shapes and error codes, so no Dart wrapper
changes. `AppDelegate` only registers them. Logic that does not need UIKit lives in plain Swift
types next to the channel, so XCTest covers it without a running app.

- **device**: `timeZone` (`TimeZone.current.identifier`), `appVersion` (the bundle's short version
  and build).
- **haptics / sounds**: each pattern in `HapticSpec.kt` maps to `UIImpactFeedbackGenerator` /
  `UINotificationFeedbackGenerator` steps (`HapticSpec.swift`, the same names); sounds play the
  same asset files through `AudioServicesPlaySystemSound` with registered system sound ids.
- **launch**: `application(_:open:options:)` and Universal Links feed one pending link; `take`
  returns it once, as on Android. The same rules as `LaunchLinks.kt`: only `wambito://` and links
  to the configured server host reach the router.
- **files**: `pick` (`UIDocumentPickerViewController`, CSV and plain text, one file, copied into
  the app's temporary directory), `save` (`UIDocumentPickerViewController` for export), `share`
  (`UIActivityViewController` from a temporary file deleted on `clearShared`). Cancelling returns
  what Android returns on cancel.
- **passkeys**: `isSupported` (true on iOS 16+), the assertion and registration calls through
  `ASAuthorizationPlatformPublicKeyCredentialProvider` with relying party `app.wambito.com` (the API
  derives it from `WEB_URL`), taking and returning the same WebAuthn JSON as the Android channel.
  Error codes map from `ASAuthorizationError` (cancelled, failed, not handled) to the Android ones.
- **notices**:
  - Permission and posting through `UNUserNotificationCenter`.
  - The guest warning: a local notification 44 days ahead, identifier `wambito.notice.guest`,
    replaced whenever Dart reschedules it (the same trigger as Android, `notice_sync.dart`).
  - "Hoy vence…": a `BGAppRefreshTask` (`wambito.notice.due`) requested with `earliestBeginDate`
    at the next 9:00 in the profile's zone. When it runs it does what `DueWorker` does (switch on,
    signed in, notifications allowed, ask the server, post or not) and requests the next one. iOS
    decides when it actually runs, so on iOS the setting's text says the notice comes "around
    9:00" (new strings in the four ARBs, chosen by platform in the settings screen) and nothing
    promises the exact hour.
  - The methods are Android's (`permission`, `requestPermission`, `scheduleDue`, `cancelDue`,
    `scheduleGuest`, `cancelGuest`). What `scheduleDue` receives (switch, zone, server) is kept in
    `UserDefaults` under the `wambito.notice.*` names `NoticeSettings.kt` uses. The background task
    reads the session the way Android's `NoticeHooks` does, from the stored session that
    `flutter_secure_storage` keeps in the Keychain; its items are written with
    `first_unlock_this_device` accessibility so a task running while the phone is locked after a
    first unlock can read them (a phone never unlocked since boot gets no notice, which is fine).

## 4. What iOS hides

- Automatic capture: `AutoCaptureSection` already renders nothing when `status()` is null, which
  is what a missing `wambito/capture` channel gives. A widget test pins it.
- Widgets: `widget_snapshot.dart` skips `HomeWidget.updateWidget` (which names an Android receiver)
  when not on Android; saving the data is harmless and stays. A test pins it. This is the only
  platform check in Dart besides the "around 9:00" text.
- Copy: no screen (onboarding included) may mention capture from notifications or widgets where
  they do not exist; any that does reads the same `status()` / platform answer.

## 5. CI and TestFlight

- Job `ios` (`macos-latest`, only when `mobile-changes` says so): `flutter pub get
  --enforce-lockfile`, `flutter build ios --release --no-codesign`, `xcodebuild test` of
  `RunnerTests` on a simulator, the two guards of §6.
- Job `ios-release` (`macos-latest`, on a pushed `mobile-v*` tag): writes `Signing.xcconfig` from
  the `IOS_TEAM_ID` secret; imports the distribution certificate (`IOS_DIST_CERT_P12`,
  `IOS_DIST_CERT_PASSWORD`) into a temporary keychain deleted at the end; `flutter build ipa
  --export-options-plist ios/ExportOptions.plist` (App Store method, automatic signing with the
  API key); uploads with `xcrun altool --upload-app` and the App Store Connect API key
  (`ASC_KEY_ID`, `ASC_ISSUER_ID`, `ASC_KEY_P8`). No fastlane, no Ruby.
- Versions come from `pubspec.yaml`: `CFBundleShortVersionString` is the version name and
  `CFBundleVersion` the build number (the base, without Play's ×10).
- From TestFlight to the store is manual in App Store Connect (listing, screenshots, review).
  `docs/mobile/ios.md` describes it, together with creating the secrets once.

## 6. Guards and tests

Written test first, everything in English.

- Dart: the capture section is hidden without the channel; the snapshot does not call
  `updateWidget` off Android; the notice setting shows the iOS text on iOS.
- Swift (XCTest, `RunnerTests`): the haptic patterns, link parsing and the server-host rule, the
  next 9:00 in a given zone (including a DST change), the 44-day guest date, the WebAuthn JSON in
  and out, the error-code mapping of files and passkeys.
- `scripts/check-channels.sh`: every `wambito/*` channel and method Dart calls exists in Kotlin and
  in Swift, except the ones listed in `.github/channel-allowlist.txt` with a reason
  (`wambito/capture  # ios-impossible`, the widget receiver, and `wambito/voice  # ios-part-two`
  until part two lands). Tested by `scripts/test-check-channels.sh`, run in CI `check`.
- `scripts/check-ios-signing.sh`: fails on a team id in `project.pbxproj` or a committed
  `Signing.xcconfig`. Run in the `ios` job.
- Deploy: `deploy/personal/apple-app-site-association.template` next to
  `assetlinks.json.template` (the team id comes from the VPS `.env`, like the Android fingerprint),
  served by Caddy at `/.well-known/apple-app-site-association` as `application/json`;
  `test-caddy.sh` checks the route and the type.
- By hand on an iPhone before the first upload: passkey sign-in, CSV import and export,
  `wambito://review/<id>`, the guest notice (with a shortened delay in a debug build), the
  background refresh forced from Xcode (`_simulateLaunchForTaskWithIdentifier`).
