# packages/db (`@wambito/db`)

Drizzle schema, SQL migrations and row-level security for Postgres.

## Entry points

- `src/schema/domain.ts` (app tables), `src/schema/auth.ts` (Better Auth tables, generated by
  `pnpm --filter @wambito/api auth:generate`).
- `drizzle/*.sql` + `drizzle/meta`: migrations; `drizzle/0001_rls.sql` holds the RLS policies.
- `src/migrate.ts` (`runMigrations`), `src/bootstrap.ts` (`ensureAppRole`, `grantAppRole`, `prepareDatabase`, `APP_ROLE`, `databaseUrl`),
  `src/client.ts`, `src/orm.ts`, `src/testing.ts` (test Postgres).
- Scripts: `pnpm --filter @wambito/db generate` (drizzle-kit), `migrate`, `bootstrap` (`--role-only`;
  `--grant-only DB` grants the app role on another database, for a restore drill).
- `testing.ts` `RESTORE_FLAGS`: the pg_restore flags `deploy/personal/restore.sh` and `backup.sh` use.

## Rules

- Migrations run as the admin/owner role, never as the runtime role (`APP_ROLE`,
  `NOSUPERUSER NOBYPASSRLS`): every user table needs RLS. Its grants are not in migrations: they
  live in `grantAppRole` (bootstrap), which `prepareDatabase` runs after the migrations.
- Add migrations with drizzle-kit; never edit an applied one (the one exception: `0001`'s grants
  moved to the bootstrap in part 2b).
- `admin_audit` is append-only: the app role has no UPDATE/DELETE on it, `grantAppRole` revokes them
  (only when the table exists, so a restore drill on a dump from before 0008 still grants).
- `records`, `key_wraps`, `pairing_requests` (0010) are the end-to-end encrypted store: `body`/`wrapped`
  are opaque `bytea` (the `bytea` custom type gives `Uint8Array`); `records.version` comes from
  `records_version_seq`, raised on every write with `set version = nextval('records_version_seq')`.
- `0011` adds the pairing `commitment`/`approver_key`/`key_v` columns, `key_wraps.attestation`
  (device wraps need it, 32 bytes) and `record_purges` (`user_id` primary key, `through_version`:
  the highest purged tombstone version, so older clients resync), with RLS like `records`.
- In production `docker compose run --rm migrate` (`deploy/personal/up.sh`) runs bootstrap +
  migrations.

## Test
